01

Architecture

A static site with no backend: nothing to patch, scale or secure at runtime. Every change goes through the same gate before it reaches a visitor.

02

The gates

JOB RUNS FAILS THE BUILD WHEN
checktsc --noEmit · eslintAny type error or lint error
buildvite buildThe production build fails
auditaxe on built pagesAny serious or critical accessibility violation
deployvercelRuns only after all three pass on main
03

The workflow

.github/workflows/ship.yml AS DESIGNED 
name: ship
on:
  push: { branches: [main] }
  pull_request:
jobs:
  check:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-node@v4
        with: { node-version: 22, cache: npm }
      - run: npm ci
      - run: npx tsc --noEmit
      - run: npx eslint .
      - run: VITE_COMMIT_SHA=$GITHUB_SHA npm run build
      - run: npm run audit   # axe against the built site

Shown as designed. Once committed, this block is replaced by the real file, linked to the repo.

04

Decisions & trade-offs

STATIC OVER SERVERA portfolio needs no runtime. Static files mean no server to patch and no backend to secure.
VITE OVER A META-FRAMEWORKNo server rendering needed; fewer moving parts to explain and maintain.
CONTENT AS FILESEach project and note is one Markdown file, versioned and reviewed like code.
